# Дизайн: улучшение скроллбара ленты миниатюр

Дата: 2026-07-04  
Затронутые компоненты: `ThumbnailStripView.xaml`, `ThumbnailStripView.xaml.cs`, `ThumbnailStripViewModel.cs` (косвенно).

---

## 1. Проблема

В ленте миниатюр (`ThumbnailStripView`) при открытии папок с большим количеством файлов (сотни–тысячи):

1. **Бегунок скроллбара становится слишком маленьким** — его трудно поймать мышкой.
2. **Прокрутка «рваная»** — `ScrollViewer.CanContentScroll="True"` заставляет `ScrollViewer` прокручивать по элементам, а не по пикселям.
3. **Клик по дорожке скроллбара не перемещает сразу в целевую точку** — по умолчанию WPF прокручивает лишь на один страничный шаг (PageUp/PageDown).

---

## 2. Цели

- Бегунок скроллбара должен оставаться удобного минимального размера независимо от количества файлов.
- Прокрутка ленты должна быть плавной (по пикселям), а не по элементам.
- Клик по любой точке дорожки скроллбара должен мгновенно перемещать ленту в эту точку.
- Выделенная миниатюра текущего файла при навигации должна центрироваться в видимой области.
- Сохранить существующую виртуализацию (`VirtualizingStackPanel`) и производительность на больших папках.

---

## 3. Нефункциональные требования

- Поддержка обеих ориентаций ленты: `Horizontal` (основной режим) и `Vertical` (альтернативный).
- Решение не должно ломать существующее поведение `ScrollIntoView` при выборе миниатюры.
- Если пиксельный скролл вызовет заметную деградацию на папках >5000 файлов — предусмотреть fallback на `CanContentScroll="True"` с фиксированным большим бегунком.
- Стиль скроллбара должен оставаться визуально согласованным с WPF-UI / Fluent Design приложения.

---

## 4. Архитектура и компоненты

### 4.1. Изменения в XAML (`ThumbnailStripView.xaml`)

- Убрать атрибут `ScrollViewer.CanContentScroll="True"` у `ListBox` (по умолчанию `False` — пиксельный скролл).
- Добавить в ресурсы `UserControl.Resources` стиль для `ScrollBar`:
  - `Thumb` получает `MinWidth="48"` для горизонтального и `MinHeight="48"` для вертикального скроллбара.
  - `Track` использует кастомные `RepeatButton` с прозрачным фоном.
  - Поведение клика по дорожке реализуется в code-behind через attached-событие или подписку на `PreviewMouseDown`/`MouseLeftButtonDown` трека.

### 4.2. Изменения в code-behind (`ThumbnailStripView.xaml.cs`)

- После `InitializeComponent()` найти внутренний `ScrollViewer` ленты через `UIHelper.FindChild<ScrollViewer>(List)`.
- Подписаться на события мыши для `Track` у горизонтального и вертикального скроллбаров.
- Обработчик клика по дорожке:
  - вычисляет относительную позицию курсора в треке;
  - вычисляет целевое смещение (`HorizontalOffset` или `VerticalOffset`) как `ratio * ScrollableLength`;
  - вызывает `ScrollToHorizontalOffset` / `ScrollToVerticalOffset`.
- Обновить `OnSelectionChanged`:
  - вместо стандартного `List.ScrollIntoView(List.SelectedItem)` центрировать выделенный элемент в видимой области через `BringIndexIntoView` + ручной корректирующий скролл, либо через `ListBoxItem.TransformToAncestor`.

### 4.3. Взаимодействие с VM

- `ThumbnailStripViewModel` не требует изменений.
- `SetCurrent` и `OnSelectedChanged` продолжают работать как раньше.

## 5. Поведение в деталях

### 5.1. Размер бегунка

- Минимальный размер бегунка фиксирован: 48 DIP по основной оси прокрутки.
- При небольшом количестве файлов бегунок остаётся пропорциональным видимой области (стандартное поведение WPF).
- При огромном количестве файлов бегунок не сжимается меньше 48 DIP.

### 5.2. Плавная прокрутка

- `CanContentScroll="False"` включает пиксельный скролл.
- Прокрутка колесом мыши и тачпадом становится плавной.
- Быстрая прокрутка через клавиатуру (Home/End/PageUp/PageDown) перемещает на соответствующие пиксельные позиции.

### 5.3. Точный прыжок по клику на дорожку

- Левый клик по пустой части дорожки (`Track`) перемещает бегунок в точку клика.
- Формула для горизонтальной ориентации:

  ```
  ratio = (mouse.X - thumbHalfWidth) / (trackWidth - thumbWidth)
  targetOffset = ratio * scrollableWidth
  ```

- Формула для вертикальной ориентации аналогична по высоте.
- Если клик пришёлся на `Thumb` — стандартное поведение перетаскивания не меняется.
- Если клик пришёлся на `RepeatButton` (стрелки / края) — стандартное поведение не меняется.

### 5.4. Центрирование выделенной миниатюры

- При смене выделенного элемента (навигация стрелками, открытие файла, клик по миниатюре) выделенная миниатюра должна оказаться по центру видимой области ленты, если это возможно.
- Если элемент ближе к краю списка, чем к центру, центрирование ограничивается границами `0` и `ScrollableWidth`/`ScrollableHeight`.

## 6. Граничные случаи

| Сценарий | Ожидаемое поведение |
|---|---|
| Лента пустая | Скроллбар скрыт, обработчики неактивны. |
| Все миниатюры влезают в окно | Скроллбар скрыт (`Auto`), обработчики неактивны. |
| Клик на сам бегунок | Обычное перетаскивание, не прыжок. |
| Клик на стрелку скроллбара | Обычное приращение на маленький шаг. |
| Быстрая смена ориентации (`Horizontal` ↔ `Vertical`) | Обработчики переподписываются на актуальный скроллбар. |
| Большая папка (>5000 файлов) | Проверяем FPS и потребление памяти; при проблемах — fallback. |
| Поддержка тач-экрана | Пинч/свайп остаются на уровне `ScrollViewer`; бегунок удобнее для точки-стилуса. |

## 7. План проверки

1. Собрать проект: `dotnet build src\Prosmotr\Prosmotr.csproj -c Debug`.
2. Опубликовать в `app\`: `dotnet publish src\Prosmotr\Prosmotr.csproj -c Release -o app`.
3. Запустить `app\Prosmotr.exe` на папке с несколькими сотнями/тысячами файлов.
4. Проверить:
   - бегунок не меньше 48 DIP;
   - прокрутка колесом плавная;
   - клик по дорожке прыгает в точку клика;
   - выделенная миниатюра центрируется при навигации стрелками;
   - переключение ориентации не ломает поведение.
5. Прогнать юнит-тесты: `dotnet test tests\Prosmotr.Tests\Prosmotr.Tests.csproj`.
6. При необходимости — замерить FPS/память на папке >5000 файлов и решить о fallback.

---

## 8. Fallback

Если пиксельный скролл (`CanContentScroll="False"`) вызовет проблемы с производительностью на больших папках:

- вернуть `CanContentScroll="True"`;
- сохранить кастомный стиль `ScrollBar` с `MinWidth`/`MinHeight` бегунка 48 DIP;
- реализовать точный прыжок по клику на дорожку вручную через `ScrollToHorizontalOffset` / `ScrollToVerticalOffset`, учитывая item-based прокрутку.
