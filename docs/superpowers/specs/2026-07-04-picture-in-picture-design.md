# Дизайн: Picture-in-Picture для видео

## Контекст

Приложение «Просмотр» использует LibVLCSharp.WPF для рендеринга видео внутри WPF-окна. Видео рисуется в отдельное нативное HWND (`ForegroundWindow` LibVLCSharp.WPF), поверх которого плавает WPF-оверлей с панелью управления. Текущая архитектура уже имеет механизм чёрного cover'а для скрытия белого фона нативного HWND при переключении видео.

## Цель

Добавить «картинка в картинке» (PiP): пользователь может вынести текущее видео в маленькое плавающее окно, а основное окно освободить.

## Поведение

- При включении PiP текущее видео продолжает играть в маленьком отдельном окне.
- Основное окно переключается на пустой/чёрный экран (согласно выбору пользователя — вариант 1).
- PiP-окно:
  - Без рамки (WindowStyle=None, AllowsTransparency=False, Background=Black).
  - Всегда поверх других окон (`Topmost=true`).
  - Сохраняет пропорции видео (16:9 для дефолтного размера, при ресайзе — не искажать).
  - Перемещается за любую точку окна при зажатой ЛКМ.
  - Размер по умолчанию 400×225 DIP (16:9), минимум 240×135, максимум 720×405.
  - Показывает мини-панель при наведении/движении мыши: плей/пауза, «вернуть в окно», закрыть PiP.
- При закрытии PiP (кнопкой × или «вернуть в окно») видео возвращается в основное окно на ту же позицию.
- При закрытии основного окна PiP тоже закрывается.
- Если в PiP дойти до конца видео — окно остаётся, видео на паузе в конце; кнопка «вернуть» или «закрыть».

## Способы включения

1. Кнопка на панели управления видео (иконка `WindowAd20` / `PictureInPicture` из WPF-UI).
2. Горячая клавиша `P` (проверяем, не занята; добавляем в настройки? — см. решение ниже).
3. Пункт контекстного меню видео (правый клик): «Окно в окне».

## Архитектура (вариант A — перенос существующего MediaPlayer)

### Компоненты

1. **`PictureInPictureWindow`** — новое WPF-окно (`FluentWindow` или обычное `Window`).
   - Содержит `LibVLCSharp.WPF.VideoView` + оверлей с мини-панелью.
   - Управляет позицией, размером, Topmost, drag.
   - Имеет свой code-behind для автоскрытия мини-панели.

2. **`PictureInPictureViewModel`** — лёгкий VM для PiP-окна.
   - Хранит ссылку на `VideoViewerViewModel`, к которому привязано.
   - Проксирует команды: TogglePlay, Close, RestoreToMainWindow.
   - Отслеживает `IsPlaying`, `PositionMs`, `LengthMs` и обновляет мини-слайдер (опционально).

3. **`VideoViewerViewModel`** — расширения:
   - Метод `EnterPictureInPicture()` — запомнить состояние, открыть PiP-окно, отвязать `MediaPlayer` от основного `VideoView`.
   - Метод `RestoreFromPictureInPicture(MediaPlayer player)` — привязать плеер обратно и продолжить.
   - Свойство `IsPictureInPicture`.

4. **`MainViewModel`** — расширения:
   - Команда `TogglePictureInPictureCommand` (CanExecute: текущий контент — видео).
   - При активации PiP вызывает `videoVm.EnterPictureInPicture()`, затем заменяет `CurrentContent` на пустой/чёрный экран.
   - При возврате из PiP — восстанавливает `VideoViewerViewModel` как текущий контент.

5. **`App.xaml.cs` / DI**:
   - Регистрируем `PictureInPictureWindow` как transient.
   - Фабрика `Func<VideoViewerViewModel, PictureInPictureWindow>`.

### Перенос MediaPlayer

- LibVLC позволяет назначать один `MediaPlayer` на одну `VideoView` (`Video.MediaPlayer = player`).
- При входе в PiP:
  1. Запомнить текущую позицию `Player.Time`.
  2. В основном окне: `Video.MediaPlayer = null` (старый `VideoView` отвязывается).
  3. В PiP-окне: `PipVideo.MediaPlayer = player`.
  4. Продолжаем воспроизведение с той же позиции (обычно не требуется seek — плеер не останавливался).
- При возврате:
  1. `PipVideo.MediaPlayer = null`.
  2. В основном окне: `Video.MediaPlayer = player`.
  3. Поднять cover, дать Render, потом привязать — чтобы избежать белого мигания.

### Основное окно при PiP

- `MainViewModel.CurrentContent` заменяем на новый лёгкий `PictureInPicturePlaceholderViewModel` → `PictureInPicturePlaceholderView`.
- Placeholder показывает:
  - Текст «Видео воспроизводится в отдельном окне».
  - Кнопку «Вернуть в окно» (вызовает возврат из PiP).
  - Кнопку «Закрыть PiP» (закрывает плавающее окно без возврата видео).
- Placeholder не содержит список недавних файлов и не дублирует стартовый экран.

### Мини-панель в PiP

- Оверлей Grid с фоном `#D91A1A1A` (как у основной панели видео), привязанный к низу окна.
- Элементы:
  - Play / Pause (символ меняется по `IsPlaying`).
  - «Вернуть в окно» (иконка `WindowAd20` или `PictureInPictureExit20`).
  - Close (иконка `Dismiss20`).
- Панель показывается при движении мыши, прячется через 3 с бездействия.

### Горячая клавиша

- `P` — включает/выключает PiP, если текущий контент — видео.
- Не добавляем в настройки в первой итерации (минимальный scope). Если понадобится — отдельная задача.
- Проверяем в `MainWindow.TryHandleHotkey`, что фокус не в TextBox/ComboBox.

## Взаимодействие с существующими механизмами

- **Single-instance:** не затронуто.
- **Fullscreen:** если основное окно в fullscreen, при включении PiP остаётся в fullscreen, но `CurrentContent` становится placeholder. Возврат из PiP восстанавливает видео в том же fullscreen.
- **Clone-режим дисплея:** PiP-окно остаётся Topmost, но перемещается в пределах виртуального экрана.
- **Автоскрытие chrome в основном окне:** не применяется к placeholder.
- **Слайд-шоу:** при включении PiP слайд-шоу останавливается (текущий контент больше не видео-VM).

## Граничные случаи

- **Переключение файла в основном окне во время PiP:** основное окно открывает другое фото/видео. PiP продолжает играть своё видео. При закрытии PiP не возвращаем видео обратно (уже другой контент) — просто останавливаем/освобождаем плеер.
- **Удаление файла в основном окне во время PiP:** если удаляем файл, который играет в PiP — `MainViewModel` должен сообщить PiP-окну закрыться или освободить handle перед удалением.
- **Закрытие основного окна:** `MainWindow.OnClosing` закрывает PiP-окно и освобождает плеер.
- **Закрытие PiP при ошибке видео:** если `HasError`, показываем плашку ошибки внутри PiP-окна и кнопку закрыть.

## Тестирование

- Ручное (основное): вход/выход PiP, пауза/воспроизведение в PiP, перемещение окна, ресайз, закрытие основного окна, удаление файла во время PiP.
- Unit: добавить тест на `NavigationService` не требуется (логика не затронута). Проверить компиляцию и существующие тесты.

## Риски

- Перенос `MediaPlayer` между `VideoView` может вызвать белое мигание. Будем использовать тот же паттерн, что и при `SwitchTo`: cover + `DispatcherPriority.Render`.
- `VideoView` LibVLCSharp.WPF создаёт отдельное `ForegroundWindow`; нужно убедиться, что PiP-окно корректно показывает overlay поверх видео.
- Закрытие PiP при активном seek/буферизации — нужен guard от `_disposed` и `_switching`.
